TRILLOKA V7.4.1 — RELIABILITY PATCH PRODUCTION DEPLOYMENT

PURPOSE
V7.4.1 is a reliability/calibration patch to V7.4.0. It does not add a new scoring philosophy or expand the checklist. It fixes cross-page evidence propagation, UNKNOWN handling, provisional-journey guardrails, commercial-scope mistakes and remediation/report presentation issues found during real-site validation.

BACKEND / RENDER
1. Replace the existing backend Python files with the V7.4.1 production files from this package.
2. Keep requirements.txt and your existing working Render build/start configuration.
3. Preserve every existing PageSpeed, access-control, payment, email and security environment variable.
4. Existing email settings remain:
   TRILLOKA_OWNER_EMAIL=onlyonearpit@gmail.com
   RESEND_API_KEY=<your Resend key>
   FROM_EMAIL=alerts@trilloka.com
5. Learning can remain enabled on Render Free, but local learning/Vault state is not durable across restarts/redeploys.

OPTIONAL PERSISTENT STORAGE — NOT REQUIRED TO RUN THE SCANNER
If/when you move to a Render plan that supports a persistent disk, mount it at /var/data and then set:
   TRILLOKA_LEARNING_DB_PATH=/var/data/trilloka_learning.db
   VAULT_DIR=/var/data/vault_archives
   TRILLOKA_SELF_SNAPSHOT_FILE=/var/data/trilloka_self_snapshot.json
   TRILLOKA_LEARNING_HASH_SALT=<long random production secret>
Recommended learning defaults:
   TRILLOKA_LEARNING_ENABLED=true
   TRILLOKA_LEARNING_AUTO_ACTIVATE_CLASSIFICATION=true
   TRILLOKA_LEARNING_AUTO_ACTIVATE_MIN_DOMAINS=12
   TRILLOKA_LEARNING_MAX_CONFLICT_RATE=0.10
   TRILLOKA_LEARNING_MAX_INFERENCE_BOOST=4.0
If no persistent disk is attached, do NOT point these paths at /var/data. Let normal defaults operate and treat learned local state as temporary.

   python -m pytest -q
   python run_all_tests.py
